### Added

- `tx.progress.runInPlan({ plan, run })` runs a step inside a progress plan of its own that always closes: on success and on a throw it cuts the plan stack back to where it was before the plan - its own plan and any plan a nested op left open - and a throw is thrown again. An extension op whose nested op throws no longer leaves its plan stuck when a caller catches the error. A balanced body reports the same progress as a hand-written `plan()` / `endPlan()` pair; runs nest, and on a query's no-op reporter it answers `run`'s result. Run plan-opening ops on one transaction one at a time: a run that ends cuts the plans of another run started after it. `deepClone` and the commit run their plans through it. `ProgressReporter` gains the method, so a custom implementation of the type must add it.
