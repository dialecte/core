### Changed

- The `dialecte-lot` and `dialecte-contributing` skills tell which flow lands a lot. A repository whose main takes changes only through the merge queue (its `.github/workflows/ci.yml` runs on `merge_group` with a `ci-ok` job) is CI-first: the lot runs the repository's pinned cli, checks only `npm run check` and `rules` on its touched files locally, commits on its own branch through the commit hook and lands with `lot land <id> --draft`, which rebases, pushes and opens the draft pull request; CI runs the suite, and the person's go queues it. No hand-over, rehearsal or merge-of-main commit there, whatever `lot status` prints (newer clis refuse the hand-over verbs there). Every other repository keeps the hand-over. The new reference `dialecte-lot/references/ci-first.md` holds the flow and the verbs that go with it (`lot start --on`, `lot forecast`, `lot pr`, `lot review`, `plan mark … superseded`, an overlap narrowed before `--overlap-ok`, the `tdd green` the hook names after a rebase).
- The landing eval cases that were set in core or the cli now name a hand-over package (nsd, plc, scl), so they keep testing the hand-over; two new cases test the CI-first landing.
