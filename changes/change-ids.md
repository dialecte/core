### Changed

- **Breaking (channel message):** a `commit` message carries `changeId: string`, one id per change: a Document's commit posts its `writeId`, a Project's undo or redo an id drawn for the step, a store's bulk write one the store draws. The writer's copy and every copy told or reposted to another tab or connection carry the same id, so a listener drops a message whose id it already applied; a commit, its undo and its redo carry three different ids. Listeners comparing whole messages, and code building `commit` messages, add the field.
- **Breaking (Store port):** `Store.commit({ writeId })` is required (a store no longer generates one): a commit without one is refused `STORE_VALUE_NOT_JSON`, nothing written. Code calling `store.commit` passes an id; a custom store drops its default.
- **Breaking (Store port):** `Store.undo` and `Store.redo` take `{ documentId, changeId }` (was `documentId`) and answer `{ changeId, changes } | false` (`HistoryStep`): the step's answer carries the id it was given, and a store that announces tells the step under it. A `changeId` missing or not well-formed text is refused `STORE_VALUE_NOT_JSON`, nothing stepped. A store that announces tells a bulk write under one id it draws per call.
- On a store that announces, a Project matches its own change with the store's announcement of it by `changeId` (it matched by type and document): a commit made on the store directly while a transaction of the same document runs is no longer taken for the transaction's.
- `STORAGE_KINDS_VERSION` is 12, the SQLite hub protocol 12 and the engine wire protocol 8: a copy of the library at an older version finds no storage kind registered by this one (`PROJECT_STORAGE_NOT_REGISTERED`), and a realm or engine of another version is refused as before.
