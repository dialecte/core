### Added

- `findByAttributes` with a list of values is one lookup, however long the list: `{ uuid: ids }` finds every element whose `uuid` is in `ids` in one store call. A store may now answer such lookups itself with the optional `Store.getByAttributes` (the records of one tag holding the given attribute values, in id order); the in-memory store does, from an attribute map it builds per tag on first use and drops at the tag's next write, so a lookup reads only the matching records. The query layer pushes the plain attributes of the filter to it (not `xsi:type`, not QName-typed attributes, never `''`), lays a transaction's staged writes over the answer from staged indexes instead of scanning every staged write, and checks the whole filter again: the same records in the same order as before. IndexedDB and SQLite stores read the tag and filter it, as before.
- `STORAGE_KINDS_VERSION` is 6: the shared `Store` shape gained `getByAttributes` and a transaction's staged operations their attribute index, so a copy of the library at version 5 finds no storage kind registered by this one (`PROJECT_STORAGE_NOT_REGISTERED`) instead of a store it reads differently.
